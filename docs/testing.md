# Проверки разработки

## Windows

Из корня проекта, PowerShell, JDK 17 и Android SDK с платформой из `compileSdk`:

```powershell
.\tools\check.ps1 -Mode Doctor
.\tools\check.ps1 -Mode Targeted -Tests 'ru.family.rasti.sync.*'
.\tools\check.ps1 -Mode Targeted -Tests 'ru.family.rasti.data.JournalFileTest','ru.family.rasti.widget.*'
.\tools\check.ps1 -Mode Full
```

`Doctor` проверяет наличие JDK/SDK/Wrapper без сборки. Это не проверка доступности
сети, прав записи кэша или способности запустить Gradle.
`Targeted` запускает выбранные unit-тесты; пустой фильтр запрещён.
`Full` запускает `testDebugUnitTest`, `lintDebug` и `assembleDebug`.
Скрипт возвращает ненулевой код при ошибке; полный лог — `.local/checks/`,
в консоли — итог или последние 60 строк. Параметры окружения после работы восстановлены.

Если SDK/кеш расположены нестандартно:

```powershell
.\tools\check.ps1 -Mode Full -AndroidSdk 'C:\Android\Sdk' -GradleCache 'C:\GradleCache'
```

Пути выше — примеры; использовать существующие каталоги своей машины.
`-Offline` разрешён, если зависимости уже загружены. Отсутствующая зависимость
в offline-режиме — причина повторить без этого параметра, а не отключать тест.

Если установленная Java выдаёт `Unable to establish loopback connection` с
`UnixDomainSockets.connect`, добавить `-WindowsSocketFallback`. Это локальный
обход ошибки Windows/JDK: недоступный каталог Unix-domain sockets заставляет JDK
использовать TCP loopback. Системная Java и настройки пользователя не изменяются.
Не создавать каталог `.local/disabled-unix-sockets`, который зарезервирован для обхода.

Если тестовые классы скомпилированы, но JDK 17/Gradle на Windows выдаёт
`ClassNotFoundException` для всех тестов из пути на кириллице, использовать
`-BuildRoot` с абсолютным путём на латинице, например `$env:TEMP/anyuta-build`,
если сам TEMP содержит только латиницу. Исходники остаются на месте; отчёты и APK
окажутся в `<BuildRoot>/app/`. Gradle-эквивалент: `-PanyutaBuildRoot=<путь>`.

## Linux и CI

```sh
./gradlew --console=plain :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
./gradlew --console=plain :app:testDebugUnitTest --tests 'ru.family.rasti.sync.*'
```

`check.yml` проверяет pull request без release-подписи и права записи в репозиторий.
`build-apk.yml` сохраняет проверки для push в main, тегов и ручного запуска.
JUnit XML и HTML/Lint-отчёты загружаются как artifacts даже при ошибке проверки.
Настройка обязательного прохождения PR-проверки в защите ветки — настройка GitHub,
она не включается одним YAML-файлом в репозитории.

## Что проверять по изменению

| Изменение | Первая проверка | Дополнительно |
| --- | --- | --- |
| JSON, локальное хранение | `ru.family.rasti.data.*` | Старые записи, повреждение файла, прерванная запись, восстановление |
| Синхронизация | `ru.family.rasti.sync.*` | 304, 409 и повторный 409, потеря сети, изменения во время запроса |
| Сон, питание, расчёты | `ru.family.rasti.sleep.*`, `ru.family.rasti.feeding.*`, нужные `ui.*Test` | Полночь, отсутствующие/пересекающиеся записи, выбранная дата |
| Виджеты | `ru.family.rasti.widget.*` | Узкий, низкий, полный размеры; действия и доступность |
| Тема, экран, диалог | соответствующие `ui.*Test` и визуальная матрица ниже | Светлая/тёмная тема, крупный шрифт, прокрутка |
| Удаление еды/сна, экспорт для LLM | `DeleteConfirmationUiTest`, `ChartsLlmExportTest`, `ChartsLlmExportUiTest` | Отмена и подтверждение, полнота и порядок данных, отсутствие имени и заметок |
| Только документация | Сверка ссылок и команд с исходниками | Не добавлять тест, который проверяет текст документа |

После изменений Kotlin, ресурсов или сборки нужен Full. Если он прошёл, не повторять
его без новой причины. Отчёты: `app/build/reports/`, XML: `app/build/test-results/`.

## Визуальная матрица

Автоматические PNG-эталоны находятся в `app/src/test/screenshots/`. Для проверки:

```powershell
.\tools\check.ps1 -Mode Targeted -Tests 'ru.family.rasti.*ScreenshotTest'
```

Для намеренного обновления после изменения UI:

```powershell
.\tools\check.ps1 -Mode Targeted -Tests 'ru.family.rasti.*ScreenshotTest' -RecordScreenshots
```

После записи просмотреть PNG и `git diff`, затем повторить проверку без
`-RecordScreenshots`. В CI запись запрещена. Gradle-эквивалент для записи:
`./gradlew :app:testDebugUnitTest --tests '*ScreenshotTest' -PrecordScreenshots=true`.
Разница и фактические изображения сохраняются в `app/build/reports/screenshots/`.
При первом запуске на другой ОС проверить переносимость эталонов; не принимать
отличия автоматически. Версии Robolectric и Compose фиксируются в Gradle.

Для UI использовать только синтетические записи, фиксированные дату/время и одинаковые
размеры устройства. Эталоны не должны содержать семейные данные, имена и токены.

- Главная, история, графики, настройки, навигация RastiApp и полные формы кормления,
  витамина и сна: светлая и тёмная темы. Сцены используют синтетические записи и
  фиксированные часы; в графиках есть оба вида питания, сон/паузы, нормы и замеры.
- ScreenScreenshotTest покрывает все сочетания двух ширин и двух fontScale,
  сохраняет дополнительные позиции прокрутки и состояния полей/чипов.
  Поля формы витамина D проверяются как общий компонент вне Dialog: Robolectric
  не достигает idle для TextField внутри окна Dialog.
  ErrorCollector позволяет получить все viewport-изображения даже при отличиях
  первых эталонов; отсутствие эталона остаётся ошибкой.
- VitaminDReminderUiTest проверяет открытый экран на границе 14:00, нажатие после
  неё, возврат на передний план, изменение времени/пояса и новый день после отметки
  витамина накануне. Pure-тест отдельно проверяет границы времени и DST.
- Ширина 320 и 360 dp; масштаб шрифта 1.0 и 1.3.
- Виджет-дашборд: 180×180, 280×100 и 320×180 dp; остальные виджеты — минимальный
  и обычный размер. Проверять на настоящем лаунчере после изменения metadata.
- Снимок нужен для затронутого состояния, а не всех экранов после любой правки.
- При намеренном изменении сначала просмотреть новый снимок и разницу, только затем
  обновлять эталон. Автоматическое принятие эталонов в CI запрещено.
- Геометрические тесты Robolectric не доказывают корректность всех лаунчеров Android.
- На устройстве проверить TalkBack, ввод/редактирование, прокрутку, поворот,
  переход из виджета, сон через полночь и восстановление сети.

## Сценарии сохранности

`JournalFileTest` проверяет первый запуск, повреждение обеих копий, неверную структуру
JSON, восстановление предыдущей копии, сохранение повреждённого оригинала, отсутствие
вытеснения резервной копии одинаковыми записями и прерванную атомарную запись.
`GitHubProtocolTest` использует поддельный транспорт: никаких запросов к GitHub,
реальных токенов и публикации сообщений. Существующие merge-тесты сохраняются.

Сетевой тест обязан проверять результат или отказ и сохранность входного состояния,
а не только число вызовов. Для новых ошибок добавлять воспроизведение причины.
